> 이 문서는 MBO-YOLO 학습 과정, 탐지 성능 분석, Vision Detector 구현, 그리고 YOLO11n 파인튜닝 계획을 정리합니다.
> 프로젝트 전체 개요는 [README.md](../README.md)를 참고해 주세요.

## 1. MBO-YOLO 학습

### 1.1 학습 환경

| 항목 | 내용 |
|------|------|
| 모델 | MBO-YOLO (커스텀 Ultralytics 8.3.56 기반) |
| 데이터셋 | URPC2020 (수중 해양생물) |
| 클래스 | holothurian, echinus, scallop, starfish (4개) |
| 데이터 규모 | 학습 5,541장 / 검증 1,200장 / 테스트 800장 |
| 학습 환경 | Google Colab, Tesla T4 GPU |
| 총 학습 | 200 epoch |

### 1.2 학습 진행 과정

학습은 단계적으로 진행되었습니다.

**시험 학습 (2 epoch, 5 epoch)**

Colab 환경 구성 후 전체 학습 파이프라인이 정상 동작하는지 검증하기 위해 소규모 epoch로 시험 학습을 수행했습니다. 생성된 `best.pt`를 Windows 로컬 환경에서 로드하고 추론이 실행되는 것까지 확인했습니다.

- Colab 새 노트북 생성 → 런타임 GPU 설정 → MBO-YOLO 저장소 Clone
- 커스텀 Ultralytics 포함 패키지 설치 → URPC2020 데이터셋 YAML 설정
- 2 epoch / 5 epoch 시험 학습으로 파이프라인 검증
- Windows에서 `best.pt` 로드 및 `seastar1.jpg` 추론 성공 확인

> 근거: Notion 20261002 진행상황 (18단계 체크리스트, 단계 1~13 완료)

**중간 학습 (80 epoch)**

시험 학습의 confidence가 매우 낮았기 때문에 80 epoch까지 학습을 진행하여 성능 변화를 확인했습니다.

- starfish 최고 confidence 약 0.227로, 여전히 저신뢰·과검출 상태
- 실용적인 탐지 성능에는 추가 학습이 필요하다고 판단

> 근거: Notion 20261004~ (80 에폭 결과 스크린샷 포함)

**본 학습 (200 epoch)**

200 epoch 전체 학습을 수행하고, epoch별 검증 성능을 분석하여 최종 가중치를 선택했습니다.

### 1.3 최종 성능 및 가중치 선택

200 epoch 학습 중 **192번째 epoch에서 최고 검증 성능**을 기록했으며, 해당 시점의 가중치를 `mbo_final.pt`로 선택했습니다.

| 지표 | 값 |
|------|-----|
| Precision | 0.764 |
| Recall | 0.591 |
| mAP50 | 0.677 |
| mAP50-95 | 0.387 |

192~199 epoch 구간에서 성능 변화가 미미하여, 현재 데이터셋과 모델 설정에서의 **수렴**으로 판단했습니다.

> 가중치 선택 및 수렴 판단: 김희수 담당

### 1.4 역할 분담

- **김희수:** Colab 본 학습 실행, epoch별 성능 분석, 수렴 판단, 최종 가중치 선택
- **황다령:** 시험 학습 환경 초기 구성 (Colab 노트북, URPC2020 준비), Windows 로컬 로드 테스트

> 근거: Notion 20261002 "언니가 해줬으면 하는 일" 항목에 "best.pt를 나중에 보내주셨으면 좋겠어요"로 본 학습을 김희수에게 요청한 기록이 있음

## 2. 일반 환경 탐지 테스트

MBO-YOLO `mbo_final.pt`를 `mbo_detector.py`와 연동하여 일반 환경(비수중) 이미지에 대한 탐지 성능을 테스트했습니다.

### 2.1 테스트 결과

| 이미지 | Conf 0.25 | Conf 0.1 | 불가사리 평균 Conf |
|--------|-----------|----------|-------------------|
| seastar1.jpg | 탐지 0개 | 불가사리 4개, 해삼 1개 | 0.1511 |
| seastar2.jpg | 성게 1개 | 성게 4개, 해삼 3개 | 미탐지 |
| seastar3.jpg | 탐지 0개 | 불가사리 1개, 해삼 2개 | 0.1099 |

### 2.2 확인 사항

- Confidence 임계값을 0.25 → 0.1로 낮추면 탐지 수가 1개 → 15개로 증가하나, 오탐도 증가
- 불가사리 검출 시 신뢰도가 0.11~0.18로 낮음
- 일부 이미지에서 서로 다른 클래스의 Bounding Box가 겹치는 현상 확인
- **원인 분석:** MBO-YOLO는 수중 이미지 중심으로 학습되어, 일반 환경에서 촬영한 사진의 탐지 성능이 낮음

### 2.3 대안 모델 테스트

| 모델 | 결과 | 비고 |
|------|------|------|
| YOLO-World | 불가사리, 조개, 성게 모두 탐지 실패 | 실험 이미지에 대한 성능 부족 |
| Roboflow Marine Organism | 불가사리 탐지 성공 | 클라우드 API 의존, 로컬 배포 미검증 |

이러한 한계로 YOLO11n 파인튜닝을 계획하게 되었습니다.

> 근거: Notion 20261010 (MBO-YOLO 해양생물 탐지 테스트 결과 정리)

## 3. Vision Detector 구현

### 3.1 이 저장소의 `vision/detector.py` (mock)

현재 이 저장소에는 실제 모델이 연결되지 않은 mock 인터페이스만 포함되어 있습니다.

- `USE_REAL_VISION = False`로 설정됨
- `mock_detect_target()`: frame에 `"FOUND"` / `"NOT_FOUND"` 문자열을 전달하여 결과를 제어
- 실제 모델 연동 시 `real_detect_target()` 내부만 구현하면 나머지 코드 변경 없이 사용 가능

### 3.2 별도 환경의 `vision/mbo_detector.py` (김희수 구현)

MBO-YOLO 모델을 사용하는 실제 탐지 모듈로, 현재 이 저장소에는 미반영 상태입니다.

**반환 구조: 3-상태 설계**

| 반환 상태 | 의미 | 설명 |
|----------|------|------|
| OK | 정상 탐지 완료 | 탐지된 객체 목록 포함 (0개도 OK) |
| FRAME_FAILED | 프레임 획득 실패 | 카메라 연결 문제 등 |
| INFERENCE_FAILED | 추론 실패 | 모델 로드 실패, 입력 형식 오류 등 |

핵심 설계: **0은 "봤는데 없었다"(OK, 탐지 0개)**, 빈 값은 **"보지 못했다"(FRAME_FAILED 또는 INFERENCE_FAILED)**.

이 구분은 LLM Agent의 시계열 판단에서 중요합니다. "이전에 3마리 있던 곳에서 0마리 탐지"(OK)와 "카메라 오류로 탐지 자체를 못 함"(FRAME_FAILED)은 전혀 다른 상황이며, 후속 행동도 달라야 합니다.

**구조 테스트:** 가짜 모델을 사용한 31개 항목 검사에서 31개 통과 확인.

## 4. YOLO11n 파인튜닝 계획

MBO-YOLO의 일반 환경 탐지 한계를 해결하기 위해, 실험 환경에 적합한 자체 데이터셋을 구축하여 YOLO11n을 파인튜닝하는 방향을 수립했습니다.

### 4.1 계획 개요

| 항목 | 내용 |
|------|------|
| 모델 | YOLO11n (사전학습 모델 기반 파인튜닝) |
| 탐지 클래스 | starfish (불가사리), scallop (가리비) — 2개 |
| 데이터 규모 | 초기 목표 약 200장 (Train 140 / Val 30 / Test 30) |
| 촬영 장비 | Go2 카메라 |
| 라벨링 도구 | Roboflow |
| 학습 환경 | Google Colab GPU |
| 추론 환경 | 로컬 PC |

### 4.2 실험 환경 구성

실제 해양 환경 대신 불가사리와 가리비 사진을 인쇄하여 벽면에 부착하는 **실내 모의 관측 환경**을 사용합니다.

**데이터 수집 조건:**

| 항목 | 조건 |
|------|------|
| 촬영 거리 | 0.5m / 1m / 1.5m |
| 촬영 각도 | 정면 / 좌측 / 우측 |
| 조명 | 밝음 / 보통 / 어두움 |
| 개체수 | 0~5개 |
| 배치 | 단일 / 다중 / 밀집 / 부분 가림 |

모든 조건을 조합하지 않으며, 실제 Go2 관측 환경을 기준으로 수집합니다.

### 4.3 데이터셋 구축 시 주의사항

- 인터넷 원본 사진만 사용하지 않고 실제 인쇄물을 Go2 카메라로 촬영
- 동일 촬영 장면의 유사 이미지가 Train과 Test에 동시 포함되지 않도록 분리
- 학습에 사용하지 않은 인쇄 사진 및 배치를 테스트 데이터로 확보
- 객체가 없는 배경 이미지도 포함하여 오탐지 여부 확인

### 4.4 시스템 연동

기존 Go2 Navigation, SQLite Observation Memory, LLM Agent 구조는 유지하고 **객체 탐지 모듈만 교체**하는 방식입니다.

```
Go2 카메라 이미지 수집
   ↓
YOLO11n 객체 탐지 (starfish / scallop)
   ↓
개체수 및 신뢰도 추출
   ↓
SQLite Observation Memory 저장
   ↓
LLM Agent 시계열 비교 판단
```

> 근거: Notion 20261010 (YOLO 기반 해양생물 객체 탐지 데이터셋 구축 및 파인튜닝 계획)
